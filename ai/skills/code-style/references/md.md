# Markdown style

## Line wrapping

- Do not hard-wrap prose at an arbitrary column just to keep lines short. Aim for roughly 140 characters per line, but treat that as guidance, not a hard limit.
- Only break a line at the end of a sentence. If a sentence would otherwise run far past the target width, breaking after a comma is acceptable as a fallback.
- Never break mid-sentence at a word boundary chosen only because it happens to land near the target width. A longer line reads better than one split at a weird spot.
- If a sentence itself is longer than the target, let the line run long rather than wrapping it awkwardly.
- Applies to prose in all Markdown files: plans, `README.md`, skill docs, `AGENTS.md`/`CLAUDE.md`, commit-adjacent notes, etc.
- Does not apply to code blocks, tables, or other non-prose content — leave those formatted as their own conventions require.
